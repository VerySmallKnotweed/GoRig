# GoRig Base: просмотр и импорт

Это первая локальная версия базы. Она работает только на том же компьютере,
где запущена программа; данные не отправляются на внешний сервер.

## Сборка и запуск на Windows

Из корня проекта:

```bat
go test ./...
go build -ldflags="-H windowsgui" -o GoRigBase.exe ./cmd/gorig-base
GoRigBase.exe
```

При первой сборке Go скачает зависимости. Компилятор C и установленный SQLite
не нужны: используется встроенный SQLite. В Windows после запуска программа
помещает значок в системный трей (он может оказаться под стрелкой скрытых
значков). Левый щелчок открывает интерфейс в браузере, правый щелчок открывает
меню с организациями и пунктом «Выход», который останавливает программу.
Щелчок по организации открывает её страницу; список обновляется при открытии меню.
Компьютеры без организации доступны в пункте «Непривязанные». Сборка с `-H windowsgui`
не открывает консоль при обычном запуске. Для диагностики используйте
`GoRigBase.exe --console`: программа присоединяется к консоли командной строки
или создаёт новую. Остановить её можно через трей или кнопку в интерфейсе.
Скрипт `build-windows.cmd` собирает оба приложения в GUI-режиме. Обычный
`go build` без `-H windowsgui` создаст консольную программу вне зависимости от ключа.

Остановить сервер можно также кнопкой «Выключить сервер» в верхней части
интерфейса. После подтверждения останется страница с сообщением об остановке;
её можно закрыть. Перед выключением сохраните изменения: несохранённый текст
пропадёт.
HTML, CSS, JavaScript, Bootstrap 5.3.8, Popper, шрифт Roboto и значки встроены в exe;
доступ в интернет и отдельная папка с файлами интерфейса для работы не нужны.
При сборке зависимости Go скачиваются только при необходимости, а во время
работы интерфейса внешние CDN не используются. Файл базы SQLite и выбранные
отчёты — пользовательские данные; они остаются отдельными файлами.
Оформление панели вдохновлено шаблоном [AdminLTE 4](https://adminlte.io/themes/v4/) от Colorlib.

Если браузер не открылся, используйте адрес из консоли, обычно
http://127.0.0.1:8765/ . Порт должен быть свободен. На других ОС программа
работает без значка в трее; используйте адрес из консоли и `Ctrl+C`.

По умолчанию `gorig-base.sqlite` создаётся **рядом с exe**. Там должны быть права
на запись. Путь можно задать явно, например:

```bat
GoRigBase.exe -db "D:\GoRig\inventory.sqlite"
```

Каталог должен существовать. Другой локальный порт можно выбрать через
`-port 8766`. Не используйте `go run` для постоянной базы без явного `-db`:
исполняемый файл при этом создаётся во временном каталоге.

## Как пользоваться

1. В «Настройках» создайте организации. Переименование сохраняет привязку всех
   компьютеров. При удалении организации компьютеры и история остаются в базе
   без организации. В обзоре показаны организации и количества по статусам.
   Пункты «Организации» и «Отчёты» открывают отдельные страницы; стрелки рядом
   сворачивают и раскрывают подменю, первоначально они раскрыты.
2. Нажмите «Импортировать отчёт», затем «Выбрать файлы» или «Выбрать папку».
   Выбор папки зависит от браузера; файлы не импортируются автоматически.
3. Нажмите нужное имя файла для просмотра и вручную выберите новый или уже
   существующий компьютер. Автоматического сопоставления нет. Укажите состояние,
   организацию и заметку; для существующего компьютера они заполняются текущими
   значениями. Изменения сохраняются вместе с успешным импортом обследования.
4. Проверьте сравнение и нажмите «Добавить в базу». Одинаковое, старое или уже
   импортированное обследование не записывается; в этом случае данные учёта не
   меняются. Изменить их можно в разделе заметок на странице компьютера.
5. На странице организации карточки компьютеров окрашены по состоянию: зелёный —
   в работе, жёлтый — в резерве, красный — выбыл. Производитель процессора
   указан отдельной меткой Intel/AMD. В блоке «Заметки и состояние» можно указать
   идентификацию (до 80 символов), тип устройства, заметку, статус и организацию.
   Тип не определяется автоматически; у старых записей он остаётся не указан.
   Эти данные можно также заполнить при импорте. Доступна история обследований. Статус «Выбыл» сохраняет всю историю.
6. Удаление компьютера после подтверждения **безвозвратно удаляет его заметки и
   все обследования**. Внешние JSON-файлы не удаляются; после удаления тот же
   отчёт можно импортировать заново. Для списания используйте статус «Выбыл».
7. В разделе «Отчёты» выберите организацию или «Всё оборудование». Документ
   группирует компьютеры по организациям и состояниям, используя последнее
   сохранённое обследование, идентификацию, тип, текущие заметки и физические накопители. Нажмите
   «Печать / Сохранить PDF» и выберите принтер или сохранение PDF в браузере.
   Полученный PDF — обычный, не сертифицированный PDF/A. При необходимости
   отключите браузерные колонтитулы в настройках печати.

Существующая база обновляется автоматически: компьютеры сохраняют свои заметки,
статусы и историю и первоначально не принадлежат организации. Перед первым
запуском новой версии остановите старую программу и сделайте копию файла базы.

История сравнивается с **последним импортированным** обследованием. Если дата
нового отчёта раньше даты последнего сохранённого, импорт блокируется, чтобы
старый отчёт не стал текущим. Поэтому отчёты одного ПК нужно добавлять в порядке
их сбора; часы на обследуемых ПК тоже должны быть выставлены правильно.

## Что сравнивается и ограничения

Сравниваются имя и идентификация компьютера, ОС (включая исходную строку версии),
выбранные значения полей компонентов и их дополнительные атрибуты. Свободное
место на логических томах и IP-адреса в сравнение не входят: оно изменяется при работе ПК. Порядок
компонентов, время и ID сканирования, версия коллектора, источники и наблюдения
не влияют на сравнение. Пустая запись об ошибке/отсутствии экземпляров WMI не
считается настоящим компонентом. Значения с `template` показываются с пометкой;
они сравниваются как текст. Пустые или недоступные поля могут измениться из-за
сбоя сбора, а не из-за замены железа. При старой версии коллектора некоторые
категории могут отсутствовать. Интерфейс предупреждает о неполных данных, но
**равенство собранных значений не доказывает, что оборудование не изменилось**.

Программа пока не распознаёт компьютеры автоматически, не импортирует всю папку
одной кнопкой и не умеет объединять карточки.
Память, размер дисков, дата установки Windows и остальные новые сведения
отображаются только если они были собраны версией коллектора, которая их
поддерживает. Первый отчёт новой версии коллектора может показать новые поля как изменения
при сравнении с более старыми отчётами.

База содержит серийные номера и пользовательские заметки. Не публикуйте её в
репозитории. Для резервной копии сначала остановите программу и скопируйте файл
базы в безопасное место. Оригинальные файлы отчётов тоже полезно сохранять.

## Значки Windows

`GoRigBase.exe` и `GoRigCollector.exe` получают встроенные значки при обычном
`go build`; дополнительные программы во время обычной сборки не нужны. Объекты
`rsrc_windows_*.syso` в каталогах команд включают значки для Windows 386, amd64
и arm64. Иконка базы в трее и favicon создаются из одного изображения
`internal/icons/base.png`; исходные ICO обоих приложений лежат в `internal/icons`.
При замене иконок необходимо сохранить PNG и многослойный ICO синхронными и
пересоздать ресурсы, например из корня проекта в командной строке Windows:

```bat
for %A in (386 amd64 arm64) do go run github.com/akavel/rsrc@v0.10.2 -arch %A -ico internal/icons/base.ico -o cmd/gorig-base/rsrc_windows_%A.syso
for %A in (386 amd64 arm64) do go run github.com/akavel/rsrc@v0.10.2 -arch %A -ico internal/icons/collector.ico -o cmd/gorig-collector/rsrc_windows_%A.syso
```

Это требуется **только при замене ICO**, не при обычной сборке. Проводник Windows
может показывать старый значок из кеша после перезаписи exe; при необходимости
обновите отображение или пересоздайте кеш значков Windows.
