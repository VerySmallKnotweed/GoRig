# GoRig Base: просмотр и импорт

Это первая локальная версия базы. Она работает только на том же компьютере,
где запущена программа; данные не отправляются на внешний сервер.

## Сборка и запуск на Windows

Из корня проекта:

```bat
go test ./...
go build -o GoRigBase.exe ./cmd/gorig-base
GoRigBase.exe
```

При первой сборке Go скачает зависимости. Компилятор C и установленный SQLite
не нужны: используется встроенный SQLite. Для запуска откройте в браузере адрес,
указанный в консоли, обычно http://127.0.0.1:8765/ . Окно программы должно
оставаться открытым; `Ctrl+C` завершает работу.

По умолчанию `gorig-base.sqlite` создаётся **рядом с exe**. Там должны быть права
на запись. Путь можно задать явно, например:

```bat
GoRigBase.exe -db "D:\GoRig\inventory.sqlite"
```

Каталог должен существовать. Другой локальный порт можно выбрать через
`-port 8766`. Не используйте `go run` для постоянной базы без явного `-db`:
исполняемый файл при этом создаётся во временном каталоге.

## Как пользоваться

1. Нажмите «Выбрать файлы» или «Выбрать папку» и выберите JSON-отчёт. Выбор папки
   зависит от поддержки браузера; если он недоступен, выберите файлы по одному
   или несколько файлов сразу. Папка не импортируется автоматически.
2. Нажмите на нужное имя в списке файлов. Отчёт отобразится без записи в базу.
   Статусы шаблонных и отсутствующих значений видны в карточках, а полный JSON
   с наблюдениями и ошибками — в раскрываемом блоке.
3. Выберите «Новый компьютер» или конкретный компьютер из базы. Автоматического
   сопоставления по имени или серийному номеру нет: пользователь решает, к какому
   компьютеру относится отчёт. Перепроверьте выбор для каждого нового файла.
4. Посмотрите сравнение. При новом компьютере или отличиях нажмите «Добавить в
   базу». Если значения совпадают, повторное обследование не записывается. Один
   и тот же `scan_id` повторно не добавляется ни к какому компьютеру.
5. В списке компьютеров можно открыть последнее обследование и историю, а также
   сохранить заметку. Исходные данные добавленных отчётов сохраняются в SQLite.

История сравнивается с **последним импортированным** обследованием. Если дата
нового отчёта раньше даты последнего сохранённого, импорт блокируется, чтобы
старый отчёт не стал текущим. Поэтому отчёты одного ПК нужно добавлять в порядке
их сбора; часы на обследуемых ПК тоже должны быть выставлены правильно.

## Что сравнивается и ограничения

Сравниваются имя и идентификация компьютера, ОС (включая исходную строку версии),
выбранные значения полей компонентов и их дополнительные атрибуты. Порядок
компонентов, время и ID сканирования, версия коллектора, источники и наблюдения
не влияют на сравнение. Пустая запись об ошибке/отсутствии экземпляров WMI не
считается настоящим компонентом. Значения с `template` показываются с пометкой;
они сравниваются как текст. Пустые или недоступные поля могут измениться из-за
сбоя сбора, а не из-за замены железа. При старой версии коллектора некоторые
категории могут отсутствовать. Интерфейс предупреждает о неполных данных, но
**равенство собранных значений не доказывает, что оборудование не изменилось**.

Первая версия не распознаёт компьютеры автоматически, не редактирует и не удаляет
их, не импортирует всю папку одной кнопкой и не умеет объединять карточки.
Видеоконтроллер, память и материнская плата отображаются только если они были
собраны версией коллектора, которая их поддерживает.

База содержит серийные номера и пользовательские заметки. Не публикуйте её в
репозитории. Для резервной копии сначала остановите программу и скопируйте файл
базы в безопасное место. Оригинальные файлы отчётов тоже полезно сохранять.
